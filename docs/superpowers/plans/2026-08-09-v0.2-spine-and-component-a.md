# Gaia v0.2 — H3 spine and Component A implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` or
> `superpowers:executing-plans`. Steps use checkbox syntax for tracking.

**Goal:** Build the H3 spatial spine for a 28,000 km² Okanagan study area, compute Component
A (vegetation structure deviation) over it, and answer the validation gate: does Component A
add discrimination over FWI + FBP fuel type under spatially-blocked cross-validation?

**Architecture:** A rasterised H3 index over a BC Albers 30 m grid turns every raster
aggregation into a `np.bincount` against a cached integer array. Component values land in
partitioned Parquet with provenance stored by reference. The validation harness trains a
gradient-boosted classifier on high-severity burn labels derived from Landsat, and compares
it against three baselines under spatially blocked folds.

**Tech Stack:** Python 3.12, h3-py v4, rasterio, shapely, pyproj, numpy, pyarrow, DuckDB,
scikit-learn. No new TypeScript in this plan.

## Global Constraints

- Every source is open and anonymous. No account, token, or API key anywhere in the path.
- Every emitted value carries provenance and uncertainty. Provenance is stored by reference
  and resolved on read; the chain returned to a caller is complete.
- v0.1's lake, schema, AOI and deployment are not modified. v0.2 writes to `data/eii/`.
- Analysis CRS is EPSG:3005 (BC Albers), grid resolution 30 m.
- H3 resolution 8 is the index unit; resolution 7 is the aggregation unit.
- Study period 2015–2024.
- Tests use fixtures, never live network calls.
- The gate wording is fixed by the spec and is not adjusted after seeing results.

## Task 3: The index raster and the aggregators

This is the load-bearing piece. Every later raster aggregation runs through it.

**Files:**
- Modify: `pipeline/src/gaia_pipeline/eii/spine.py`
- Test: `pipeline/tests/eii/test_spine.py`

**Interfaces:**
- Produces:
  - `class Spine` with `cells: pa.Table`, `grid: AnalysisGrid`, `index: np.ndarray[int32]`
    (−1 where no cell), and `n_cells: int`
  - `Spine.build(area, cache_dir) -> Spine` — rasterises cell boundaries once and caches
  - `Spine.mean(values, mask) -> tuple[np.ndarray, np.ndarray]` — per-cell mean and the
    fraction of the cell that carried data
  - `Spine.majority(values, mask) -> tuple[np.ndarray, np.ndarray]` — per-cell modal class
    and its share
  - `Spine.fraction(flag) -> np.ndarray` — per-cell fraction of pixels where flag is true

- [ ] **Step 1: Write failing tests** on a three-cell toy spine:
  - `mean` of a constant raster returns that constant, with fraction 1.0
  - masked pixels are excluded from `mean` and lower the fraction
  - `majority` returns the modal class and never a class absent from the cell
  - a cell with no valid pixels returns NaN with fraction 0.0
  - the index raster assigns every pixel to at most one cell
- [ ] **Step 2: Run and watch them fail.**
- [ ] **Step 3: Implement.** Rasterise with `rasterio.features.rasterize` over the boundary
  polygons reprojected to EPSG:3005, burning the row index of each cell. Aggregate with
  `np.bincount(index[valid], weights=values[valid], minlength=n_cells)` divided by counts.
  Majority uses a bincount over `index * n_classes + class_code`.
- [ ] **Step 4: Run tests, then commit.**

## Task 5: Source adapters

Six adapters, one file each, all sharing the same shape: fetch from an anonymous endpoint,
land on the spine's grid, return an array plus a `SourceRecord`. These are independent of
one another and can be built in parallel.

**Files:**
- Create: `pipeline/src/gaia_pipeline/eii/sources/bcgw.py` — WFS client, bbox-paged,
  GeoJSON out. Layers: `BEC_BIOGEOCLIMATIC_POLY`, `VEG_COMP_LYR_R1_POLY`,
  `FWA_STREAM_NETWORKS_SP`, `FWA_LAKES_POLY`, `FWA_WETLANDS_POLY`.
- Create: `pipeline/src/gaia_pipeline/eii/sources/canopy.py` — GLAD Potapov 2019 30 m North
  America mosaic, windowed read, reprojected to the spine grid.
- Create: `pipeline/src/gaia_pipeline/eii/sources/nbac.py` — per-year perimeter zips from
  CWFIS, filtered to the study area.
- Create: `pipeline/src/gaia_pipeline/eii/sources/fbp.py` — national FBP fuel-type raster,
  windowed read from EPSG:3978, nearest-neighbour reprojection (class codes).
- Create: `pipeline/src/gaia_pipeline/eii/sources/landsat.py` — Landsat C2 L2 via Earth
  Search; pre-fire and post-fire growing-season composites; NBR, dNBR, RBR.
- Create: `pipeline/src/gaia_pipeline/eii/sources/weather.py` — Open-Meteo ERA5-Land daily,
  noon values, plus the FWI code chain.
- Test: one test module per adapter under `pipeline/tests/eii/sources/`.

**Interfaces:**
- Every adapter exposes `fetch(spine, **params) -> tuple[np.ndarray, SourceRecord]` except
  `nbac.perimeters(year) -> list[Perimeter]` and `weather.fwi_series(lat, lon, start, end)
  -> pa.Table` with columns `date, ffmc, dmc, dc, isi, bui, fwi, vpd_kpa`.
- `SourceRecord` carries dataset, version, access route, native resolution, native timestep,
  citation, retrieved timestamp.

- [ ] **Step 1 (per adapter): Write failing tests against recorded fixtures.** Fixtures are
  small real responses saved under `pipeline/tests/eii/fixtures/`, captured once by a
  `--record` flag and committed. No test touches the network.
- [ ] **Step 2: Run and watch them fail.**
- [ ] **Step 3: Implement the adapter.**
- [ ] **Step 4: Run tests. Commit per adapter.**

**FWI specifics.** Check PyPI for a maintained implementation before writing van Wagner's
equations by hand. If none is suitable, implement from the published equations with the
standard day-length tables, and validate against the CWFIS station archive
(`cwfis_fwi1950sv3.0.csv.bz2`) for a station inside the study area: agreement within
rounding on DC, DMC and BUI is the test.
