# Gaia v0.2 — Ecosystem Integrity Index and the agent surface for it

**Status:** approved 2026-08-09
**Supersedes:** nothing. v0.1 stays live and unmodified.
**Source:** `~/Downloads/compass_artifact_wf-4f6d9210-642d-50c3-9806-2138df11d19c_text_markdown.md`

## The claim we are trying to earn the right to make

Landscape ecological condition explains variance in wildfire burn severity beyond what fire
weather and static fuel maps explain, it can be measured from open data at a resolution
that is useful to an underwriter, and an agent can query it with every number carrying its
provenance and its uncertainty.

That is one empirical claim and one engineering claim. The empirical one is falsifiable and
is gated below. The engineering one is the part we can guarantee.

## What v0.2 is not

- Not a hazard index. FWI exists; we are not rebuilding it.
- Not a property-level vulnerability score. That is Z-FIRE's lane and it sits above ours.
- Not multi-peril, not outside southern British Columbia, not real-time.
- Not validated against insurance claims. Severity and a structure-loss case study are
  proxies, and every artefact says so in those words.
- Not a public deployment. v0.2 ends with a local MCP server and scripted demos.

## Decisions taken before any code

Five forks were settled in brainstorming. Each is recorded here because the reasoning
matters more than the choice.

**1. No accounts.** Every source is open and anonymous. v0.1 promises a cold start with no
credentials and that promise is part of why the layer is credible to someone evaluating it
without talking to us. The prompt's Earth Engine plan is rejected; substitutes exist for
every component it names, and each substitution is a recorded divergence.

**2. Extent: Okanagan plus adjacent interior, roughly 25,000 km², 2015–2024.** Not the
prompt's 200,000 km². The claim needs enough independent fire events for spatially disjoint
folds, not maximum area, and 25,000 km² of interior BC across ten years contains more
burned ground than the coastal AOI has ever seen. Kelowna, West Kelowna and the McDougall
Creek footprint are inside it. Extending later is a config change because the H3 spine does
not care how large the polygon is.

**3. The MCP surface extends the existing TypeScript server.** The prompt specifies FastMCP
in Python. v0.1 already ships an MCP server bound to `@gaia/service`, with REST as a second
adapter over the same functions, and the provenance guard that makes a bare number
structurally unserveable lives in `@gaia/core` and walks every response on the way out.
Building a second server in Python means reimplementing that guard, which is the one
mechanism this product is actually about. Divergence recorded.

**4. Partitioned Parquet, provenance by reference, served locally.** Twenty-five million
rows with a JSON provenance chain each is several gigabytes; the v0.1 lake already ships
inside a Vercel function under a 250 MB ceiling. EII values write to Parquet partitioned by
year and component, with provenance stored as references into small dimension tables and
resolved at read time. The chain returned to a caller is identical to v0.1's — it is simply
not duplicated twenty-five million times on disk. v0.1's lake, schema and deployment are
untouched.

**5. Target is high-severity classification within burned area.** Train inside NBAC
perimeters, 2015–2024, target = RBR above a published high-severity threshold, aggregated
to H3. This answers "given this ground burns, does it burn severely", which is the question
Parks 2018 and Whitman 2018 established and where the white space is. Burn probability was
rejected: it is an occurrence question dominated by ignition and weather, which is the FWI
lane. Structure loss is a case study, never a training target, because BC publishes no open
structure-loss dataset.

## The gate

Written before the first model is fitted, and not adjusted afterwards:

> Component A, added to baseline_3 (FWI + FBP fuel type), produces a positive Δ AUC-PR
> whose bootstrap 95% confidence interval excludes zero under spatially-blocked
> cross-validation with 2–3 km buffers, and does not worsen calibration.

If it misses, that is the result. We report the negative finding, narrow the scope, and do
not add components until something scores.

## Architecture

New work lives inside `~/gaia-layer`. v0.1's coastal AOI, lake and deployment are additive
neighbours, not migration targets.

| Path | Responsibility |
|---|---|
| `pipeline/src/gaia_pipeline/eii/` | H3 spine, five components, composite, constraint rules |
| `pipeline/src/gaia_pipeline/eii/sources/` | one adapter per external dataset |
| `pipeline/src/gaia_pipeline/validate/` | spatial CV, baselines, metrics, retrodiction |
| `data/eii/` | partitioned Parquet archive plus a slim DuckDB catalog |
| `service/src/eii.ts` | query layer, shared by the MCP server and the REST API |
| `docs/plans/09..14-*.md` | one milestone record per sub-project |

### The spatial spine

H3 resolution 8 (~0.74 km² per cell) is the index unit; resolution 7 is the aggregation for
portfolio queries. Cells are written once to a dimension table carrying cell id, resolution,
centroid, boundary, parent id and the intersection weights against each source grid.

Every component writes a narrow fact row:

```
(h3, period, component, value, uncertainty_type, uncertainty_value,
 method_id, run_id, source_set_id, constraint_flags)
```

Provenance resolves by reference against `method`, `run`, `source_set` and `source` tables.
Nothing from v0.1's 20 m projected grid is reused. Two spines, one query interface; forcing
either onto the other damages whichever one loses.

### Data sources

All anonymous, all open.

| Component | Source | Access |
|---|---|---|
| A — structure deviation | BC VRI: crown closure, height, age | BCGW WFS, bbox-filtered |

| | BEC subzone-variant map — the reference frame | BC Data Catalogue |
| | ESA WorldCover 10 m | S3, already wired in v0.1 |
| B — water balance | ERA5-Land via Open-Meteo | already wired in v0.1 |
| | MODIS ET, or ERA5-Land P−ET if it needs a login | verify at build |
| C — riparian condition | BC Freshwater Atlas streams, lakes, wetlands | BC Data Catalogue |
| D — fuel moisture | FWI codes from ERA5-Land noon values | computed |
| E — drought | SPEI, 1/3/12-month | SPEIbase download |
| target | NBAC fire perimeters, 1972–present | CWFIS Datamart |
| target | burn severity | CanLaBS if it exists; else dNBR from Landsat C2 L2 via Earth Search |

Three substitutions against the prompt, each to be recorded in `docs/DIVERGENCES.md`:

- **ETH canopy height instead of GEDI L2A.** GEDI needs an Earthdata login; the ETH product
  is the wall-to-wall fused version of the same measurement.
- **Computed FWI instead of Earth Engine or a CWFIS scrape.** Van Wagner's equations are
  published and deterministic. PyPI is checked for a maintained implementation first;
  reimplementing a standard is the wrong default.
- **Landsat C2 L2 via Earth Search instead of HLS**, same login reason.

Two verify-at-build items, not to be papered over: whether an open Canadian burn-severity
product covers our years (if not, the imagery pipeline the prompt told us to cut returns,
for the target variable only), and whether MODIS ET is reachable without a token.

### Component A

Per H3 cell: canopy height from ETH, crown closure and stand age from VRI, cover class from
WorldCover. Each z-scored against the reference distribution for its own BEC
subzone-variant and cover class, so "dense" means dense *for this biogeoclimatic context*.

The sign is not asserted. Parks 2018 makes live fuel the dominant variable group; Whitman
2018 found open high-basal-area stands burning less severely. Component A therefore stores
signed z-scores per structure variable plus a documented combination whose direction is
published in the methodology resource as a hypothesis the validation tests. If the
validation contradicts it, the methodology changes and says why.

### Components B–E

Built only after the gate is answered. B: rolling water-balance anomaly plus antecedent soil
moisture. C: riparian area fraction per cell weighted by vegetation condition. D: normalised
DC/BUI and VPD composite. E: normalised multi-scale SPEI blend. EII is a documented weighted
sum, equal weights initially, refined by validation, never a black-box blend. Components and
composite are both persisted.

### The model

`HistGradientBoostingClassifier` from scikit-learn: one new dependency, native categorical
and missing-value handling, no compiler. Features are Component A's z-scores, terrain
(elevation, slope, aspect, heat load), fire weather at burn date (FWI, DC, BUI), and FBP
fuel type as a categorical.

Baselines, trained and validated identically: `baseline_1` FWI only, `baseline_2` FBP only,
`baseline_3` both.

### The constraint layer

Extends v0.1's constraint engine idiom rather than inventing a second one. Rules:

1. **Monotonicity.** Higher DC, BUI or VPD, and lower soil moisture, must not decrease
   predicted severity, all else equal. Checked by partial-dependence sign.
2. **CFFDRS consistency.** Predicted severity must respect FBP rate-of-spread ordering for
   the cell's fuel type.
3. **Water-balance sanity.** Cells in intact riparian or wetland context are not assigned
   top-decile severity without an overriding weather signal.

A violation clamps to the plausible envelope or returns the value flagged low-confidence,
and always logs the rule that fired. Nothing implausible is emitted silently. FBP is treated
as a lossy prior, not ground truth: Baron 2024 found no suitable fuel-type match for 58% of
field plots in interior BC, which is itself part of the argument for this index existing.

### Validation

Spatially blocked cross-validation with 2–3 km buffers between folds, plus a temporal
hold-out training on ≤2020 and testing on 2021 and 2023. Both are reported separately. A
random split is not reported at all: published wildfire-susceptibility work shows random
splits inflating AUC from ~0.6 to ~0.99, and that number would be a lie.

Reported: AUC-ROC, AUC-PR, Brier, reliability curve, per-fold uncertainty maps, and Δ
against each baseline with bootstrap 95% CIs. Output includes a one-page actuary-readable
summary: what was predicted, against what truth, lift over baselines, uncertainty, and the
leakage controls used.

The Kelowna 2023 retrodiction runs as-of pre-fire over the McDougall Creek footprint and
reports whether Traders Cove and Wilson's Landing were flagged before the fire — including
the misses. Structure-loss counts (189 reported by the Central Okanagan EOC in August 2023,
revised to 303 in BC's 2025 investigation; 13,970 ha; CAD 480M insured per IBC/CatIQ) are
case-study context and are labelled as such.

### The agent surface

Resources: `eii://schema`, `eii://catalog`, `eii://methodology`, `eii://validation`.

Tools: `get_eii`, `get_component`, `explain_score`, `compare_baseline`, `portfolio_scan`.

All implemented in `service/`, exposed through the existing MCP server and REST adapter,
both already wrapped by the provenance guard. Every response carries provenance,
uncertainty, and a `method_justification` field stating what the number can and cannot
support at its native resolution. Every tool call and response appends to an audit table.

`explain_score` reads precomputed per-component contributions rather than invoking a live
model, the same way v0.1 serves its substrate decomposition. This keeps explanations
auditable instead of regenerated per call.

## Testing

Tests before implementation. Network fixtures, never live calls, in the test suite. The
numeric claims are pinned the way the milestone-8 layer tests were:

- H3 join weights sum to one and conserve area
- z-scores respond correctly to a shifted reference distribution
- each constraint rule fires when it should and stays quiet when it should not
- metric implementations match hand-computed values
- the spatial-CV splitter never places a training cell within the buffer of a test cell

## Build order

Each stage is a milestone doc and a set of commits. Nothing past the gate is built until the
gate is answered.

1. **Spine** — study-area polygon, H3 dimension tables, Parquet archive layout, catalog
   schema, provenance-by-reference tables.
2. **Component A and the validation harness** — sources, z-scores, target variable,
   baselines, spatial CV, metrics. **Gate.**
3. **Components B–E** — only on a pass.
4. **Constraint layer.**
5. **Agent surface** — resources, tools, audit log.
6. **Kelowna retrodiction and demo scripts.**

## Risks

- **The gate fails.** Planned for. The negative result ships with the reasons and the
  narrowed scope.
- **A source turns out to need a login.** Substitutions are pre-specified for the two most
  likely (MODIS ET, severity product). Anything else gets recorded and worked around, not
  silently swapped.
- **VRI coverage or currency is worse than assumed.** Verify early; ETH canopy height is
  wall-to-wall and can carry Component A alone if VRI proves unusable.
- **Ten years of severity data is a large ingest.** The archive builds incrementally by year
  so a failure costs one year, not the run.
